## 4. AES67 interoperability (the key question)

Can an A&H Dante card in AES67 mode subscribe to multicast flows from a non-Dante Linux sender? **Yes**, with the constraints below, and without Dante Domain Manager.

Rules for AES67 flows received by a Dante device (Glensound guide quoting Audinate; Yamaha whitepaper; Dante Controller help):
- Multicast only, non-redundant, destination 239.nnn.0.0/16 (default prefix 239.69.x.x), UDP port 5004. Brooklyn II, HC, Broadway, Brooklyn 3 (≤ fw 4.2.x) and Zynq IP Core (≤4.2.x) subscribe **only** in 239.x/16. Receiver's "RTP Multicast Address Prefix" must match the sender's prefix or the subscription looks OK but no audio flows.
- 48 kHz only; L16 or L24; packet time 125 µs / 250 µs / 333 µs / 1 ms accepted on RX (Dante TX is 1 ms L24 only); **≤ 8 channels per stream**. 32 ch = 4 flows.
- Discovery via SAP (30 s announce interval); non-Dante senders appear as blue "virtual transmitter" devices in Dante Controller; subscribe by clicking the routing grid. External SDP sessions can also be added manually (newer Controller).
- Clock: PTPv2 default profile (domain 0); Dante AES67-enabled devices do PTPv1 and v2; one PTP master only; the Dante device can be master and the Linux sender slave (that is how aes67-linux-daemon does it).
- Dante Domain Manager: **not required**. The AES67 tab is only hidden when a device is enrolled in a domain (then DDM controls it); AES67 works on unmanaged networks.
- Enabling AES67 mode requires a device reboot; DVS and Via do not support AES67 mode.
- Sources: [Glensound AES67/Dante guide](https://www.canford.de/ProductResources/resources/G/Glensound/Bella/Glensound%20AES67%20Dante%20guide.pdf), [Dante Controller: AES67 Config](https://dev.audinate.com/GA/dante-controller/userguide/webhelp/content/aes67_config.htm), [RTP Config tab](https://dev.audinate.com/GA/dante-controller/userguide/webhelp/content/rtp_config_tab.htm), [AES67 & ST2110-30](https://dev.audinate.com/GA/dante-controller/userguide/webhelp/content/aes67_and_smpte_st2110-30_audio.htm), [Yamaha "Connecting AES67"](https://oss.yamaha.com.cn/files/20250106/Connecting_AES67_en.pdf), [Sonifex FAQ](https://sonifex.co.uk/technical/faq/Dante_AES67_Mode_and_Multicast_Configuration.pdf), [Q-SYS how-to](https://support.qsys.com/en_US/application-notes/how-to-%7C-setting-up-an-aes67-stream-on-a-dante-device), [aes67.app](https://aes67.app/post/configure-aes67-on-dante-devices)

## 5. Latency

- Native Dante: receiver latency settings 0.25 / 0.5 / 1 (default) / 2 / 5 ms; transmit latency ≈ 1/3 of receive setting (Yamaha). 0.25 ms only for direct Gigabit links.
- AES67 flows into a Dante receiver: "The receive latency for AES67 Rx flows is set to 2 ms, this setting is not affected by changing the latency setting in Dante Controller" (Glensound, quoting Audinate behaviour); Yamaha whitepaper: "2 ms fixed latency for reception"; Merging: "in AES67 mode Dante devices' minimal latency is 1 ms, lower values won't be accepted; set 2 or 5 ms; AES67 recommended 3 ms"; Audinate/Yamaha 2018 deck: "AES67 default is 3 ms, Dante defaults to 1 ms". Newer firmware exposes an "RTP Latency" field (values not published). So plan on **2–3 ms** on the Dante side plus the sender's packetisation (1 ms) and buffering: aes67-linux-daemon ≈ 4 ms measured end-to-end; ESP32-P4 claims 0.7 ms. Budget 3–6 ms base-station→console for the AES67 route vs ≈1 ms for native Dante hardware.
- DVS: 4–10 ms + ASIO buffer; Dante Via: ~10 ms + USB/driver buffer (10–15 ms typical, 30 ms reported in one Cubase setup).
- Sources: [Glensound guide](https://www.canford.de/ProductResources/resources/G/Glensound/Bella/Glensound%20AES67%20Dante%20guide.pdf), [Yamaha/SVC whitepaper](https://www.svconline.com/resources/whitepaper-connecting-yamaha-dante-devices-with-other-aes67-devices), [Audinate/Yamaha 2018 deck](https://my.audinate.com/sites/default/files/PDF/beyond-certification-tips-tricks-best-practices-dante-aes67-january-2018-audinate-yamaha-pres.pdf), [QSC Dante latency blog](https://blogs.qsc.com/systems/?p=2539), [Merging PDF](https://www.merging.com/uploads/assets/Installers/ravenna/Configure%20Merging%20and%20AES67%20Devices.pdf)
